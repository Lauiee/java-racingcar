## 1차 리뷰 이후 리팩토링
### - MVC 패턴에 대해 재차 공부 후 리팩토링 방향 결정

#### - Model의 역할에 대해 고민
  - 너무 엔티티처럼 생각한 것이 문제로 보임
  - 수정방향: 모델 객체 내에서도 비즈니스 로직을 포함하도록 변경
  - 추가로 파싱된 자동차의 경우 검증역시 Model에서 진행하도록 변경, 이 역시 객체의 무결성을 보장해주게 될 것
  - 만약 모델에 지나치게 많은 로직이 포함되게 되면 문제가 될 수 있음 -> 그때 Service 계층으로 분리 시도

#### - MVC의 각 역할 명확하게 구분 및 적용
  - View계층에선 사용자의 입력 및 출력 로직 처리
  - Controller계층에선 View와 Model을 연결

#### - 오버 엔지니어링이 된 팩토리 계층 제거 -> 생성에 대한 책임 역시 모델 계층으로 이동
  - 정적 팩토리 메서드를 이용해 생성
  - Car는 단순 생성이기에 new 사용 / Cars의 생성 로직은 다소 복잡하기에 정적 팩토리 메서드 이용
  - 이를 통해 객체 생성의 캡슐화 및 가독성 향상 

#### - View계층으로 검증 로직 이동, 이로써 View계층에서 무결성을 보장하게 함 (+ 검증 계층 생략으로 구조 간략화)
